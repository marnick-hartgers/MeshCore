# Implementation plan — Design 4 (Icon Tile Launcher)

Design chosen: [`design-4-icon-tiles.md`](design-4-icon-tiles.md). This doc
sequences the actual code changes across `examples/companion_radio/ui-forest/`,
grounded against the real classes/APIs (not just the design brief) — file
paths, function signatures, and line numbers below were confirmed by reading
the current source, not assumed.

Ships all four `phases/ToDo.md` asks together, in this order, because each
later phase depends on the one before it:

1. **New icon assets** — everything else draws on these.
2. **Status bar rewrite** — establishes the GPS-fix/transport-connected state
   helpers the dashboard's tiles reuse, so this has to land first or the
   dashboard would duplicate that logic.
3. **Home dashboard screen** — the new `_home`.
4. **Retire legacy Home rows into Settings/Diagnostics** — safe to do once the
   dashboard no longer needs them as flat Home rows.
5. **Ambient notification blink** — smallest, independent change; done last
   since it's the least risky and easiest to verify in isolation.
6. **Cleanup & verification**.

Scope note: v1 ships the fixed 8-tile grid identically on every display size
(GPS, Buzzer, Contacts, Channels, Signal, Diagnostics, Settings, Advert) — no
user-configurable stat tiles yet, since those 8 already saturate the 128x64
grid exactly. The bigger-panel expansion (128x128 boards growing to a 4x3 grid
with hand-picked top-10 stats in the extra slots, per `design-4-icon-tiles.md`)
is **explicitly deferred**, not part of this plan — see "Deferred / future
work" at the bottom.

## Decisions this plan locks in (resolving `plan.md`'s open questions for Design 4)

| Question | Decision | Why |
|---|---|---|
| Status bar icon budget | New ~8x8 icon set, `statusBarHeight()` stays 11px | Per `plan.md` §1's own recommendation — doesn't cost any of the tight content area on 128x64 boards. |
| Transport icon | One generic link/plug glyph for all transports (BLE/USB/WiFi/Ethernet) | Avoids per-build icon variants; cheap to swap later if a BLE-specific glyph is wanted for BLE builds only. |
| `Screen_Recents` destination | `Screen_Diagnostics` (new row) | Confirmed by reading `Screen_Settings*`: every Settings sub-screen's rows are config (Toggle/Stepper/Enum/Action), not data browsers — `Screen_Diagnostics` already mixes read-only stat rows the same way `Screen_Recents` would fit, and uses the identical `MenuItem[]`-array pattern to extend. |
| `Screen_RadioInfo` destination | Verify overlap with `Screen_DiagRadio` first (task 4.2 below); delete if redundant | Both are radio-parameter readouts — likely near-duplicates, not confirmed without a field-by-field diff. |
| `Screen_Bluetooth` destination | `Screen_SettingsNetwork` | It's a transport-enable toggle + PIN display — same shape as that screen's existing Toggle rows. |
| `Screen_Advert` tile behavior | Tile pushes the **existing** `Screen_Advert` instance (`_nav.push(_advert)`), not a fire-and-forget call | Confirmed by reading `Screen_Advert.cpp`: it's a press-to-arm confirmation screen that also owns the toast/log/`notify()` side effects on send — not a passthrough, so skipping it would lose that behavior. |
| Signal tile data source | Ship it, gated behind the same `signal_bars` verification caveat already flagged in `icons.h`/`plan.md` | See Phase 3, task 3.4 — flagged as a go/no-go gate specifically for that one tile, not the whole plan. |

Phase-5 comment block: small script-generated byte arrays, not hand-typed, to
avoid transcription errors nobody here can compile-check against real
hardware).

| Icon | Size | Purpose | Notes |
|---|---|---|---|
| `buzzer_on_icon` | 16x16 | Home tile (Buzzer, on state) | New — no "on" glyph exists today, only the 8x8 `muted_icon` ("off"). |
| `advert_icon_16` | 16x16 | Home tile (Advert) | New — today's `advert_icon` is 32x32 (used as `Screen_Advert`'s full-screen glyph); shrink/redraw, don't reuse the 32x32 bitmap directly at the wrong scale. |

| `link_off_8`, `link_disconnected_8`, `link_connected_8` | 8x8 each | Status bar transport indicator | New — generic link/plug glyph per the decision above, 3 states. |
| `buzzer_on_8` | 8x8 | Status bar buzzer indicator (on state) | New; the existing `muted_icon` (8x8) is reused as the "off" state — no new asset needed for off. |
| `unread_envelope_8` | 8x8 | Status bar unread-count indicator | New. |

Existing assets reused as-is for Home tiles (no changes needed): `gps_fix_icon`

## Phase 2 — Status bar rewrite

Grounded in `StatusBar.h/.cpp` and `UITask.cpp:399-419` (`updateStatusBar()`)
as they exist today.

### 2.1 — Drop the marquee entirely
Removing the node name (moves to the dashboard's caption line, Phase 3) means
`StatusBar` never needs to show variable-width text again. Delete: `_text`,
`_text_width`, `_scroll_x`, `_next_scroll`, `_needs_redraw`'s scroll-related
branches, `_is_eink`'s marquee-disable branch, `setText()`, and the
scrolling/ellipsized branches in `render()` (`StatusBar.cpp:87-118`). This is a
net simplification, not just a swap — no more per-frame scroll-position state,
no more e-ink-vs-non-e-ink text branch.

### 2.2 — New fixed icon slots
Replace with fixed-position icon draws, left-to-right: GPS (8x8) · transport
(8x8) · buzzer (8x8) · unread envelope+digit (8x8 + text) — battery gauge
stays exactly as-is, right-aligned, unchanged code
(`StatusBar::renderBattery()`). New `StatusBar` public API:

```cpp
enum class GpsState { Off, NoFix, Fixed };
enum class LinkState { Off, Disconnected, Connected };

void setGpsState(GpsState s);
void setLinkState(LinkState s);
void setBuzzer(bool on);          // replaces the muted-only overlay logic
void setUnreadCount(int count);   // clamp display at "9+" past 9
// setBattery(uint16_t mv, bool muted) — keep signature, drop the muted-icon
// side effect from it now that setBuzzer() owns that icon in its own slot.
```

### 2.3 — Wire the two previously-unused real signals
- **GPS fix**: add a small helper (reused by Phase 3's dashboard tile too, so
  write it once) that maps `SensorManager::getLocationProvider()`'s
  `isValid()`/enabled-setting into a `GpsState`. Today's `getGPSState()`
  (`UITask.cpp:583-593`) only checks the on/off setting — extend it (or add a
  sibling function) to also consult `LocationProvider::isValid()` when GPS is
  on, matching what `Screen_Gps.cpp:29-44` already does.
- **Transport connected**: combine `isSerialEnabled()` (already wired) with
  `hasConnection()` (`AbstractUITask.h:42-43`, fed from `_serial->isConnected()`
  in `MyMesh.cpp:2274`, today only consumed by `Screen_Status`) into a
  `LinkState`. Same reuse-once note as GPS — Phase 3's dashboard GPS/link
  tiles should call the *same* helper functions as `updateStatusBar()`, not
  duplicate the state→icon mapping in two places.
- **Unread count**: `_msgcount` already exists (`UITask.h:173`) — just pass it
  through to `setUnreadCount()`.

### 2.4 — Update `UITask::updateStatusBar()`
Replace the `snprintf(...)` + `setText()` call (`UITask.cpp:405-417`) with the
four new setter calls above. Delete `stripNonAscii()`
(`UITask.cpp:389-397`) from here — it moves to Phase 3, since the dashboard's
name line is the only remaining consumer of it.

**Files touched**: `StatusBar.h`, `StatusBar.cpp`, `UITask.cpp`
(`updateStatusBar()`, `getGPSState()`/new GPS-fix helper), `icons.h` (icons
already added in Phase 1).

## Phase 3 — Home dashboard screen

New class, replacing `MenuScreen* _home`. Base contract confirmed from
`src/helpers/ui/UIScreen.h`: `render(DisplayDriver&)` returns ms-until-next-
render (every existing screen just returns `1000`), `handleInput(char c)`
returns whether the key was consumed, `poll()` defaults to no-op.

### 3.1 — New files: `Screen_HomeDashboard.h` / `.cpp`

```cpp
class Screen_HomeDashboard : public UIScreen {
  NavStack& _nav;
  UITask* _task;
  UIScreen* _contacts;   // = existing _contacts instance
  UIScreen* _channels;   // = existing _channels instance
  UIScreen* _diagnostics;// = existing _diagnostics instance
  UIScreen* _settings;   // = existing _settings instance
  UIScreen* _advert;     // = existing _advert instance (Screen_Advert*)
  int _focus = 0;        // 0..7, row-major
  unsigned long _caption_revert_at = 0;

  void renderTile(DisplayDriver& display, int idx, int x, int y, int w, int h);
  const uint8_t* iconFor(int idx);   // maps live state -> current icon bitmap

public:
  Screen_HomeDashboard(NavStack& nav, UITask* task, UIScreen* contacts,
                       UIScreen* channels, UIScreen* diagnostics,
                       UIScreen* settings, UIScreen* advert);
  int render(DisplayDriver& display) override;
  bool handleInput(char c) override;
};
```

Constructor takes existing screen instances by pointer (same pattern every
other screen already uses to reference shared singletons — see how
`Screen_Settings`'s constructor takes the 5 sub-screens) — **no new screen
instances are created for Contacts/Channels/Diagnostics/Settings/Advert**,
this class just holds references to the ones `UITask::begin()` already builds.

### 3.2 — Layout math (128x64 reference; formulas, not hardcoded pixels, so
bigger panels degrade gracefully even before the deferred bigger-grid work)

```cpp
int content_top = Layout::statusBarHeight(true);              // 11
int caption_h   = Layout::rowHeight(1);                        // 11
int grid_h      = display.height() - content_top - caption_h;  // 42 on 128x64
int cell_w      = display.width() / 4;
int cell_h      = grid_h / 2;
// tile idx -> col = idx % 4, row = idx / 4
// icon drawn centered in its cell: icon_x = x + (cell_w-16)/2, icon_y = y + (cell_h-16)/2
```
`grid_h` at 42px / 2 rows = 21px per row — comfortably fits a 16x16 icon
centered with margin, matching `Layout::iconRowHeight()`'s existing "16px icon
+ margin" reasoning (`Layout.h:44-47`) without needing that exact helper
(it's list-row-shaped, not grid-cell-shaped, so this class computes its own
cell geometry rather than reusing it — same "don't force a helper built for a
different shape" judgment `Layout.h`'s own comments already apply elsewhere).

### 3.3 — Focus highlight
Reuse `MenuScreen`'s exact convention (`MenuScreen.cpp:62-68`) since there's no
`invertRect` primitive on `DisplayDriver` — focus = `fillRect` the tile's cell
bounds in `LIGHT` (routed through `Layout::accentColor()`, not raw `GREEN`,
unlike `MenuScreen`'s own minor inconsistency there — no need to replicate
that one), then `setColor(DARK)` and draw the icon on top so it reads as a
cutout, exactly like a selected menu row.

### 3.4 — Per-tile icon source (`iconFor(int idx)`)
| idx | Tile | Icon logic |
|---|---|---|
| 0 | GPS | `gps_off_icon`/`gps_nofix_icon`/`gps_fix_icon` via the **same** GPS-fix helper Phase 2.3 wrote for the status bar (call it, don't reimplement) |
| 1 | Buzzer | `muted_icon` (off) / `buzzer_on_icon` (on) via `isBuzzerQuiet()` |
| 2 | Contacts | `contact_icon` (static) |
| 3 | Channels | `channel_icon` (static) |
| 4 | Signal | `signal_bars[level]` — **gate this behind verifying the RSSI "no packet yet" sentinel** per radio backend first (the same caveat `icons.h:199-207` already flags); if not verified before this phase is implemented, ship a safe static placeholder (e.g. `event_log_icon` reused, or omit the live level and just show a fixed "radio" glyph) rather than risk showing "full signal" before any packet has ever been heard. |
| 5 | Diagnostics | `event_log_icon` (static) |
| 6 | Settings | `settings_icon` (static) |
| 7 | Advert | `advert_icon_16` (static) |

### 3.5 — Caption line
Device name (via `stripNonAscii()`, moved here from `UITask.cpp`) shown by
default; on any `_focus` change, swap to `"<Tile label>: <live value>"` for
~2-3s (store `_caption_revert_at = millis() + N`), then revert. Draw via
`display.drawTextEllipsized(...)` (already handles both fixed- and
variable-width font metrics, `DisplayDriver.h:77-112`) in case a long device
name or long focused-tile value would overflow.

### 3.6 — Input handling
- `KEY_NEXT`/`KEY_PREV`: `_focus = (_focus + 1) % 8` / `(_focus + 7) % 8`,
  reset `_caption_revert_at`. Return `true`.
- `KEY_ENTER`/`KEY_SELECT`, dispatch on `_focus`:
  - GPS (0): call the existing `toggleGPS()`-equivalent function already used
    by `Screen_Gps`/referenced in `FormField.h`'s staged-commit comment — grep
    for its exact call site before writing this, don't reintroduce a second
    GPS-toggle code path.
  - Buzzer (1): same, existing `toggleBuzzer()`-equivalent.
  - Contacts/Channels/Diagnostics/Settings/Advert (2,3,5,6,7): `_nav.push(target)`.
  - Signal (4): no-op (glance-only, matches `design-4-icon-tiles.md`'s original
    intent for stat tiles that aren't Advert).
- `KEY_HOME` needs no handling here — already intercepted globally by
  `UITask::loop()` before dispatch, per the existing architecture.

### 3.7 — Wire into `UITask`
- `UITask.h`: change `MenuScreen* _home;` to `Screen_HomeDashboard* _home;`.
  Remove `MenuItem _home_items[UI_FOREST_HOME_ITEM_COUNT];`,
  `int _home_item_count;`, and `#define UI_FOREST_HOME_ITEM_COUNT 13`
  (`UITask.h:77`) — no longer needed once tiles are hardcoded in the new
  class rather than built as a generic `MenuItem[]`.
- `UITask.cpp:88-199`: delete the entire `int i = 0; ... _home_items[i]...`
  build-up and the `_home = new MenuScreen(...)` line; replace with:
  ```cpp
  _home = new Screen_HomeDashboard(_nav, this, _contacts, _channels,
                                    _diagnostics, _settings, _advert);
  ```
  (`_contacts`, `_channels`, `_diagnostics`, `_settings`, `_advert` are already
  constructed earlier in `begin()`, `UITask.cpp:51-86` — unchanged.)
- `_msg_preview`/`_splash` construction (`UITask.cpp:200-202`) and
  `gotoHomeScreen()` (`UITask.h:201`, `_nav.reset(_home)`) need **no changes**
  — both only need a `UIScreen*`, which `Screen_HomeDashboard*` satisfies.

**Files touched**: new `Screen_HomeDashboard.h`/`.cpp`, `UITask.h`, `UITask.cpp`.

## Phase 5 — Ambient notification blink while connected

Grounded in `UITask::newMsg()` (`UITask.cpp:214-229`), `NotificationPrefs.h`,
and `ToastOverlay.h` as they exist today. Confirmed: no existing mechanism
already does "brief, non-intrusive cue" — `ToastOverlay` is a full-screen
takeover overlay (unsuitable), and the LED's blink pattern
(`userLedHandler()`, `UITask.cpp:362-381`) is a free-running heartbeat keyed
only on `_msgcount > 0`, not a per-event trigger. This phase adds new, minimal
state rather than repurposing either.

### 5.1 — Add a flash timer to `StatusBar`
The unread badge lives in the status bar (Phase 2), which is drawn on *every*
screen (`UITask::loop()` composites it on top of whatever the current screen
just rendered) — putting the flash there, not on the dashboard, means the cue
is visible regardless of which screen the user is currently on, matching
"ambient" rather than "only visible if you happen to be on Home."

```cpp
void StatusBar::flashUnread() {  // call from UITask::newMsg()
  _unread_flash_until = millis() + 1500;
}
// in render(): if (millis() < _unread_flash_until) invert the badge's fillRect
// the same fillRect-then-contrasting-color trick used everywhere else in this
// codebase for "highlighted" (§3.3) -- no new drawing primitive needed.
```

### 5.2 — Change `UITask::newMsg()`'s connected branch
Current code (`UITask.cpp:214-229`) always does `_nav.reset(_msg_preview)`
and only gates the *display wake* on `hasConnection()`. New behavior:

```cpp
void UITask::newMsg(uint8_t path_len, const char* from_name, const char* text, int msgcount) {
  _msgcount = msgcount;

  if (hasConnection()) {
    _status_bar.flashUnread();   // ambient cue only -- no nav change, no wake
  } else {
    _msg_preview->addPreview(path_len, from_name, text);
    _nav.reset(_msg_preview);
    if (_display != NULL && !_display->isOn()) {
      _display->turnOn();
    }
  }
  if (_display != NULL && _display->isOn()) {
    _auto_off = millis() + AUTO_OFF_MILLIS;
    _next_refresh = 100;
  }
}
```
The `!hasConnection()` branch is unchanged behavior (full interrupt, since the
device is the only place the user will see the message) — only the
`hasConnection()` branch changes, from "silent, nothing visible" to "ambient
badge flash, no takeover."

**Files touched**: `StatusBar.h`, `StatusBar.cpp`, `UITask.cpp` (`newMsg()`).

## Phase 6 — Cleanup & verification

- Grep for any remaining references to deleted symbols (`Screen_Status`,
  `UI_FOREST_HOME_ITEM_COUNT`, `_home_items`, `stripNonAscii` at its old call
  site) to make sure nothing dangling is left.
- **No automated test coverage exists for this** — `pio test -e native` only
  compiles `src/Utils.cpp`/`src/Packet.cpp` against googletest and never
  touches `examples/companion_radio/ui-forest/` (Arduino-only code, excluded
  from the native env's `build_src_filter`). Verification has to be a compile
  + manual smoke test:
  - `pio run -e <board>_companion_radio_ble` (or whichever transport) for at
    least one board per `DisplayDriver` class, to catch
    `supportsColor()`/`isEink()`-branch mistakes early rather than on a single
    board:
    - one 128x64 mono OLED (e.g. `RAK_4631`)
    - one e-ink board (e.g. `lilygo_techo`)
    - one color board (e.g. `heltec_rc32`)
  - On-device/emulated smoke test checklist: all 8 tiles render with correct
    icons in both states where applicable (GPS off/no-fix/fix, Buzzer on/off);
    focus highlight moves correctly through all 8 with wraparound; ENTER
    flips GPS/Buzzer inline without navigating away; ENTER on
    Contacts/Channels/Diagnostics/Settings/Advert pushes the right screen and
    `KEY_CANCEL`/`KEY_PREV` correctly pops back to the dashboard; status bar
    icons update live for all 4 indicators plus the unread badge; a message
    arriving while connected flashes the badge without changing screens or
    waking a sleeping display; a message arriving while disconnected still
    shows the full `Screen_MsgPreview` interrupt exactly as before.

## Deferred / future work (explicitly out of scope for this plan)

- Growing the grid to 4x3 on 128x128 panels with hand-picked top-10 stats in
  the extra slots (`design-4-icon-tiles.md`'s bigger-panel mockup) — v1 ships
  the same fixed 8-tile grid on every display size.
- Verifying `signal_bars`' RSSI sentinel behavior across all six radiolib
  wrapper backends (blocks nothing but the Signal tile's live icon, per Phase
  3.4's fallback).
